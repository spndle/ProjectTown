# 工具调用与沙箱：让 Agent 安全地改变环境

## 1. 工具调用的基本流程

Agent 不应直接操作操作系统，而应向运行时提交结构化请求：

```json
{
  "tool": "write_file",
  "arguments": {
    "path": "README.md",
    "content": "# 示例项目"
  }
}
```

运行时负责校验参数、执行工具，并返回成功状态、结果摘要、错误类型和耗时。模型随后只能根据这份真实回执决定下一步。

## 2. ProjectTown v0.1 的工具

- `list_directory`：观察工作区中的文件。
- `write_file`：在工作区内创建文本产物。
- `check_markdown`：检查 Markdown 文件是否具有有效标题和正文。
- `check_python_syntax`：在不执行代码的情况下检查 Python 语法。

这些工具足以演示一个初步 Agent 闭环，同时把副作用限制在 Sandbox 内。

## 3. 路径边界

工具收到的路径必须是相对于 Quest 工作区的路径。运行时需要规范化路径，并确认最终位置仍位于 Sandbox 根目录中。`../`、绝对路径以及解析后逃逸出 Sandbox 的路径都应被拒绝。

这条规则很重要：提示词中的“只访问指定目录”属于软约束，而路径解析和边界检查才是可执行的硬约束。

## 4. 错误处理

错误至少应区分无效参数、越界路径、文件不存在、内容校验失败和内部错误。v0.1 会把错误写入 Trace，并停止当前 Quest；后续版本会在此基础上增加重试策略、幂等键和模糊副作用协调。
