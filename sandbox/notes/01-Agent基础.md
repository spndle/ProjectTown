# Agent 基础：从聊天模型到行动系统

## 1. Agent 是什么

大语言模型负责根据上下文产生下一段内容；Agent 则在模型之外增加目标、状态、工具和控制循环，使系统能够观察环境并采取行动。一个最小 Agent 循环可以写成：

```text
读取目标与当前状态 → 选择下一步动作 → 调用工具 → 观察结果 → 更新状态 → 判断是否结束
```

模型提出动作，但环境状态才是事实。例如，模型说“README 已经创建”并不能证明任务完成；系统还需要检查文件是否存在及内容是否有效。

## 2. 最小组成

- **Goal**：用户想要得到的最终结果。
- **Plan**：从当前状态到目标状态的步骤序列。
- **State**：当前任务、步骤以及环境的结构化信息。
- **Tool**：读取目录、写入文件、运行检查等有限能力。
- **Observation**：工具执行后返回的真实结果。
- **Termination**：成功、失败或达到预算时停止循环。

## 3. 为什么采用结构化动作

自由文本难以可靠执行。ProjectTown 要求 Agent 生成工具名和参数组成的结构化动作，再由运行时校验。这样可以提前发现不存在的工具、缺少的参数和越界路径，并将每次调用记录成可查询的 Trace。

## 4. v0.1 的范围

v0.1 使用单 Agent 和线性里程碑，重点是跑通“创建 Quest—规划—执行—查看结果”的闭环。它还没有长期任务所需的目标契约、独立验证器、断点恢复和循环检测；这些能力将在后续版本逐级加入。
