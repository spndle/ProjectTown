# 可靠执行与评测：不要相信 Agent 的自我报告

## 1. 常见失败模式

长任务 Agent 经常出现以下问题：

- 执行过程中逐渐偏离原始目标；
- 工具失败后重复相同动作；
- 将失败回执误判为任务成功；
- 程序重启后丢失进度；
- 反复执行已经产生副作用的操作；
- 没有环境证据，却直接宣称任务完成。

## 2. 状态机比聊天历史更可靠

ProjectTown 将 Quest 显式表示为 `planned`、`running`、`completed` 或 `failed`。每个里程碑也有自己的状态。只有工具执行和检查结果才能推动状态转移，而不是依靠自然语言中的“我已完成”。

## 3. Trace 的作用

一条可用的 Trace 应记录：

- 执行的是哪个 Quest 和里程碑；
- Agent 提议了哪个工具和哪些参数；
- 工具是否成功、返回了什么摘要；
- 调用耗时以及失败原因；
- 状态何时从计划中变为执行中，最终为何结束。

Trace 让开发者能够复现问题，并计算任务成功率、工具调用数和执行时延等初始指标。

## 4. 从 v0.1 到可靠 Agent

v0.1 只建立最小闭环。v0.2 将引入 Goal Contract、独立 Verifier 和 Evidence，防止 Agent 自我宣告完成；v0.4 再加入事件溯源、Checkpoint、幂等调用及故障恢复；更高版本会处理计划漂移、停滞循环和受限重规划。
